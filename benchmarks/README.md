# Benchmarks

CPU/GPU benchmark scripts and results (Phase 4-5, extended Phase 7).
Full written analysis of everything these scripts produce lives in
`../BENCHMARK_REPORT.md`.

- `cpu_vs_gpu.py` -- **done, verified on real GPU hardware.** Four
  sweeps -- matmul forward+backward across tensor size, an MLP across
  depth, the Phase 3 CNN architecture across batch size, and a full
  TransformerLM training step across (seq_len, batch_size) -- each
  timed on CPU and (when available) GPU with proper
  `cupy.cuda.Stream.null.synchronize()` barriers, saved as a CSV + a
  log-log latency plot per sweep into `results/`. Run
  `python cpu_vs_gpu.py --quick` for a fast smoke test or
  `python cpu_vs_gpu.py` for the full sweep; see `--sweep` to run just
  one. Written and CPU-smoke-tested in the dev sandbox, then actually
  run on a free Kaggle GPU notebook (2x Tesla T4, `pip install
  cupy-cuda12x` matching the CUDA version `nvidia-smi` reports) to
  reproduce; results show up to 14.7x speedup at scale.
- `grad_check.py` -- **done.** Runs every Phase 1-3 op/layer/loss
  through finite-difference gradient checking and renders one Markdown
  report table (30/30 checks passed). The individual checks already
  exist as pytest assertions across `tests/test_ops.py`,
  `test_grad_check.py`, `test_layers.py`, and `test_attention.py`
  (which is what actually gates correctness); this script re-runs the
  same methodology in one place for the aggregated report. Run
  `python grad_check.py --out results/grad_check_report.md`.
- `convergence_curves.py` -- **done.** Parses the saved training logs
  in `../examples/results/*_output.txt` and plots loss (and, for the
  CNN, accuracy) vs. epoch for both Phase 3 examples. Run
  `python convergence_curves.py`.
- `mixed_precision.py` -- **done (CPU half).** Phase 7's fp16-vs-fp64
  numerical-error table, a direct gradient-underflow measurement
  (with/without `GradScaler`), a synthetic update-underflow demo, and
  a 4-configuration DigitsCNN convergence study (fp32 reference vs.
  three fp16 configurations). Run
  `python mixed_precision.py --out results/mixed_precision_report.md`.
- `mixed_precision_gpu.py` -- **done, verified on real GPU hardware.**
  fp32 vs. fp16 throughput (matmul/mlp_depth/cnn_batch_size/
  transformer_step, same architectures as `cpu_vs_gpu.py`) and real
  peak CUDA memory via CuPy's memory pool, CUDA-only (no CPU column --
  see the script's docstring for why fp16 has no CPU throughput
  story). Actually run on a Kaggle GPU notebook (2x Tesla T4): fp16
  matmul reaches 7.3x speedup at n=2048, and fp16 uses exactly half
  the memory of fp32 at every width tested. The first Kaggle run of
  this script's memory sweep hit a real reference-cycle/`gc.collect()`
  bug (see `../BENCHMARK_REPORT.md` Section 5.7); fixed and re-verified.
  Run `python mixed_precision_gpu.py --quick` on a free Kaggle GPU
  notebook.
- `checkpoint_memory.py` -- **done, verified on real GPU hardware.**
  Gradient checkpointing's wall-clock overhead on CPU (~1.1-1.7x
  across stack depths 2-32) always runs; `--gpu-memory` additionally
  measures real peak CUDA memory, checkpointed vs. not. Actually run
  on Kaggle: saves up to 84% peak GPU memory at depth 32, growing
  steadily from 28% at depth 2 as expected. Run
  `python checkpoint_memory.py` (CPU) or
  `python checkpoint_memory.py --gpu-memory` (Kaggle).
- `results/` -- generated CSVs and plots, regenerated by running the
  scripts above. Currently populated with the actual Kaggle GPU run's
  Phase 4-5 output plus Phase 7's CPU- and GPU-side results (all real,
  not placeholders) -- see `../BENCHMARK_REPORT.md` for what each file
  means.
